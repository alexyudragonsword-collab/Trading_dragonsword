# Sector Management

管理 `universe.py` 中的两级股票池结构（顶级板块 → 子板块 → 股票）。

## 数据结构

```
SECTOR_MAP = {
    "顶级板块A": {
        "子板块1": ["TICK1", "TICK2", ...],
        "子板块2": [...],
    },
    "顶级板块B": { ... },
}
```

## 用法

```
/sector <名称>
```

`$ARGUMENTS` 可以是：
- 已有顶级板块名（如 `半导体`、`科技`）
- 已有子板块名（如 `Memory`、`中国科技股`、`Magnificent Seven`）
- 任意新名称 → 引导新建流程

---

## 执行步骤

**参数：** $ARGUMENTS

### Step 1 — 识别参数

读取 `universe.py` 的 `SECTOR_MAP`，判断 `$ARGUMENTS` 属于：

| 情况 | 处理 |
|------|------|
| 匹配顶级板块 | → Step 2A |
| 匹配子板块 | → Step 2B |
| 未匹配（新名称） | → Step 2C |

---

### Step 2A — 操作顶级板块

列出该顶级板块下所有子板块及其股票数量，然后询问用户想做什么：

- **查看子板块**：列出指定子板块的股票详情 → 转 Step 2B
- **新建子板块**：在该顶级板块下新增子板块 → 引导输入名称和股票
- **重命名顶级板块**：修改 `SECTOR_MAP` 中的 key
- **删除顶级板块**：移除整个顶级板块及其所有子板块和股票（**二次确认**，说明将删除的股票总数）

---

### Step 2B — 操作子板块

- 显示归属顶级板块
- 以表格列出当前股票（代码 + 公司全名）
- 如有因全局去重被其他子板块优先占用的股票（如 NVDA），标注说明
- 询问用户操作：

  - **添加股票**：用户提供代码 → 确认交易所格式（见注意事项）→ 写入
  - **删除股票**：用户指定代码 → 从该子板块移除
  - **替换股票**：删除旧代码，添加新代码
  - **重命名子板块**：修改对应 key 名称
  - **移动子板块**：将整个子板块移至另一顶级板块（询问目标顶级板块）
  - **删除子板块**：移除整个子板块及其股票（**二次确认**，说明将删除的股票数）
  - **仅查看**：不做修改，结束

---

### Step 2C — 新建流程

1. 询问用户确认名称
2. 询问类型：**新顶级板块** 还是 **新子板块**

   **新顶级板块**：
   - 在 `SECTOR_MAP` 末尾新增顶级 key（初始无子板块）
   - 询问是否立即在其下新建子板块

   **新子板块**：
   - 询问归属哪个已有顶级板块（列出当前所有顶级板块供选择）
   - 若需归属全新顶级板块，先执行新顶级板块流程
   - 在对应顶级板块下新增子板块（初始为空列表）
   - 询问要添加哪些股票（代码 + 确认交易所格式）

3. 写入 `universe.py`

---

### Step 3 — 提交

如有任何修改，更新 `universe.py`，然后 commit 并 push 到当前分支。

---

## 注意事项

- 公司名称从已知知识库提供，不调用外部 API
- 非美股需确认正确的 yfinance 后缀格式：
  - 港股：`XXXX.HK`
  - 韩股：`XXXXXX.KS`
  - 台股：`XXXX.TW`
  - 上交所：`XXXXXX.SS`
  - 深交所：`XXXXXX.SZ`
- **全局去重规则**：`ALL_TICKERS` 中每只股票只出现一次，以 `SECTOR_MAP` 中第一次出现的子板块为主归属；`SECTOR_MAP` 直接渲染时允许跨子板块重复显示
- `scorer.py` 的因子组与股票板块结构无关，新建/删除板块无需修改评分引擎
- 不要创建 Pull Request，除非用户明确要求
